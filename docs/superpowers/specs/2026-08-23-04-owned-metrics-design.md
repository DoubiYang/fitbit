# 自建恢复、睡眠与训练负荷指标设计

**状态：** 草案，待用户审阅
**日期：** 2026-08-23
**对应工作项：** 4. 定义自建恢复、睡眠、训练负荷指标

## 1. 目标与边界

Google Health 的 Readiness、Sleep Score、Cardio Load 不是公开 API 字段，且其算法不可复制。一期建立自己的透明指标，为 AI 教练提供稳定输入，并让用户能查看指标来源、基线和缺失数据。

这些指标用于生活方式与训练自我观察，**不用于诊断疾病、预测受伤或替代专业医疗建议**。

## 2. 共同设计原则

1. 每个分数都能展开为原始输入、个人基线、时间范围和版本。
2. 使用个人历史而非人群排名；同一用户的趋势比跨用户比较更重要。
3. 数据不足时显示“校准中”或低置信度，而不是生成漂亮但不可靠的数字。
4. 算法采用版本化配置；历史结果保存所用版本，避免悄悄改分。
5. 先提供可解释的规则模型，积累数据后才评估是否需要学习型模型。

## 3. 基线与数据质量

### 基线

- 初始校准：计算某个睡眠日期 `D` 的分数时，只使用严格早于 `D` 的历史日，避免当天数据进入自己的基线。少于 14 个有效历史日时不显示恢复或睡眠完整度；有 14–27 个时显示分数和“临时基线”；有至少 28 个时形成完整个人基线。
- 基线窗口：从 `D` 之前向后取最近 `min(28, 有效历史日数)` 个有效日；使用中位数和稳健离散度（如 MAD）减小异常日影响。临时基线的窗口就是当时实际取得的 14–27 日，不补零、不混入更早日期。
- 生命体征基线按同一测量条件比较，例如优先使用夜间/晨间 HRV 与静息心率。

`有效日`定义为同一用户本地日期上有一段主睡眠，且在 HRV、RHR、实际睡眠分钟三项**原始数据**中至少具备两项；这样校准期不会依赖尚未生成的睡眠完整度。形成或使用完整 28 日基线时，用户数据源的最近一次成功同步必须距计算时刻不超过 36 小时；历史记录不会因其原始写入时间较早而失效。若同日存在多个候选记录，使用来源优先级最高且时间覆盖最长的一条。

`睡眠日期`固定为主睡眠结束时的用户 IANA 时区本地日历日。例如周一 23:30 至周二 07:00 的主睡眠归到周二。主睡眠按以下顺序唯一选择：先取提供方明确标为 `isMainSleep=true` 且结束于该睡眠日期的记录；若没有，取结束于该日、睡眠或卧床时长至少 180 分钟的记录。候选中先取实际睡眠分钟最多者，再按来源优先级、开始时间最早、记录 UUID 字典序决胜。午睡不进入主睡眠选择。所有原始时间先按记录当时保存的时区转换；没有记录时区时使用用户在该记录创建时的 IANA 时区快照，绝不使用服务端当前时区重算历史。

对某个子分数，先以上述窗口选择共同有效日，再只保留该子分数对应字段存在且通过范围校验的日值；不足 14 个日值时，该子分数不可用。HRV、RHR 与睡眠各自可用的历史日数须单独展示。

### 数据质量

每次计算附带 `high`、`medium`、`low` 或 `calibrating`：

- `high`：核心输入完整、28 日完整基线已形成、同步新鲜；
- `medium`：一个非核心输入缺失，或正在使用 14–27 日临时基线；
- `low`：核心输入缺失、设备未同步或存在明显异常；
- `calibrating`：有效数据不足 14 天。

低质量数据只显示原始趋势和补数提示，不输出强训练建议。

## 4. 恢复信号（Recovery Signal）

### 用户目的

了解身体今天相较于自己的常态，是更适合恢复、维持训练，还是可以尝试较高负荷。

### 输入与权重

| 输入 | 默认权重 | 比较方式 |
| --- | ---: | --- |
| 夜间/晨间 HRV | 40% | 与个人 28 日基线的相对偏离；较高通常更好。 |
| 静息心率 | 30% | 与个人基线的反向偏离；持续升高需要说明。 |
| 睡眠完整度 | 30% | 使用本文件定义的昨夜睡眠指标。 |

对 HRV 和 RHR 使用以下确定性变换。令 `m` 为第 3 节为目标睡眠日期选出的 14–28 个、该字段可用的历史日中位数，`MAD` 为同一集合的中位数绝对偏差，`s = max(1.4826 × MAD, floor)`；其中 HRV 的 `floor = 5 ms`，RHR 的 `floor = 3 bpm`。

`z = (今日值 − m) / s`

- `HRV 子分 = clamp(50 + 15z, 0, 100)`；
- `RHR 子分 = clamp(50 − 15z, 0, 100)`；
- `睡眠子分 = 本文件第 5 节的睡眠完整度`。

恢复信号为可用子分按默认权重加权平均，并把可用权重归一化至 100%。少于两项核心输入时不生成分数，仅显示“数据不足”；有两项但用户数据源最近成功同步距计算时刻超过 36 小时时最多给 `low` 质量。`clamp(x, 0, 100)` 表示将结果限制在 0 到 100。

### 输出

- 分数：0–100，仅表示相对个人近期状态；
- 状态：`恢复优先`（0–39）、`维持`（40–69）、`状态较好`（70–100）；
- 解释：最多三条，例如“HRV 比 28 日中位数低 16%，且昨夜少睡 70 分钟”；
- 不确定性：基线长度、缺失输入和异常测量提示。

不使用红黄绿配色作为医疗风险信号，也不把状态表述为“可以安全高强度训练”。

## 5. 睡眠完整度（Sleep Completeness）与睡眠债

### 用户目的

区分“睡了多久”“睡得是否连续”“作息是否稳定”，而非只给一个神秘睡眠分数。

### 输入与权重

| 输入 | 默认权重 | 定义 |
| --- | ---: | --- |
| 睡眠时长达成度 | 40% | 实际睡眠时长相对于用户设置睡眠目标。 |
| 睡眠效率 | 25% | 睡眠时长 / 卧床时长；无卧床时长则不计入。 |
| 清醒中断 | 15% | 夜间清醒总时长与次数的趋势性惩罚。 |
| 作息规律性 | 20% | 入睡/起床时间与最近 14 日个人常态的偏离。 |

为避免实现歧义，子分数固定为：

- `时长达成度 = clamp(100 × 实际睡眠分钟 / 用户目标睡眠分钟, 0, 100)`；
- `睡眠效率 = clamp(100 × 实际睡眠分钟 / 卧床分钟, 0, 100)`；
- `清醒中断 = clamp(100 − 0.75 × 夜间清醒分钟 − 5 × 清醒片段数, 0, 100)`，清醒片段仅计时长至少 5 分钟的睡眠阶段；
- `作息规律性 = clamp(100 − 0.8 × (|入睡时间−14日中位入睡时间| + |起床时间−14日中位起床时间|), 0, 100)`，时间差以分钟计。

`作息规律性`中的入睡时间使用可比较的跨午夜坐标：令 `b` 为入睡本地钟点的午夜后分钟数；若 `b < 720`，令 `B = b + 1440`，否则 `B = b`。因此 23:30 为 1410、00:30 为 1470，两者相差 60 分钟；该规则不做环形取模。起床时间一律为主睡眠结束时刻的午夜后分钟数。14 日中位入睡/起床时间均取目标睡眠日期之前最近 14 个具有对应时间的主睡眠日（不得包含目标日）；少于 14 个时不计算规律性子分。

睡眠完整度为可用子分按表中权重归一化后的加权平均。若没有卧床时长或清醒阶段，则不计算相应子分并降低质量；若缺少实际睡眠时长，则不生成睡眠完整度。若全部可用子分的归一化权重不足原始总权重的 40%，不生成分数。用户必须能设置和修改自己的睡眠目标；系统不替用户做医学化的“最佳睡眠需求”判断。

### 睡眠债

`近 7 日睡眠债 = Σ max(0, 用户睡眠目标 − 每日实际睡眠时长)`

睡眠债用“累计少睡时长”展示，而不是夸张的风险标签。午睡是否抵扣由产品设置明确说明；一期默认单独展示午睡，不自动完全抵扣主睡眠债。

## 6. 训练负荷（Training Load）与平衡

### 用户目的

知道自己最近的运动刺激相较于个人习惯是偏低、相近还是增加过快。

### 负荷算法

一期使用可解释的心率区间负荷：

`会话负荷 = Σ(每个心率区间停留分钟数 × 区间权重)`

若存在分钟级心率，使用心率储备百分比 `p = (HR − RHR) / (HRmax − RHR)` 分区：`p < 0.50`、`0.50–<0.60`、`0.60–<0.70`、`0.70–<0.80`、`p ≥ 0.80`；权重分别为 1、2、3、4、5。优先使用用户明确设置的 `HRmax`；否则使用 `208 − 0.7 × 年龄`，且计算时 RHR 取会话开始前最近有效日的值。每个心率样本按覆盖分钟计入对应区间。

若仅有会话汇总而无区间数据，使用 `会话分钟 × 强度权重` 的降级算法：低/中/高强度的权重分别为 1/3/5，强度取提供方的会话强度标签；没有标签则该会话不产生训练负荷，标示为 `low` 数据质量。此降级结果不可与分钟级结果混用为高置信比较。

日负荷为训练会话负荷加总；日常低强度活动可单独展示，默认不混入训练负荷，避免把通勤和正式训练混为一谈。

### 训练—恢复平衡

- **短期负荷：** 最近 7 日平均日负荷；
- **长期参考：** 最近 28 日平均日负荷；
- **负荷比：** 短期负荷 / 长期参考；
- **恢复上下文：** 最近 3 日恢复信号和睡眠债趋势。

只有过去 28 日至少有 14 个有效训练日，且长期参考至少为 5 负荷点时才显示负荷比；否则显示“训练基线校准中”。负荷比小于 0.80 显示“低于近期习惯”，0.80–1.30 显示“接近近期习惯”，大于 1.30 显示“增加较快”。零短期负荷在已有长期基线时为 0；分母不足时绝不相除。它不是伤病预测器，也不是让用户强行完成的目标。

## 7. AI 教练使用规则

AI 只能访问已计算的指标、原始证据摘要和数据质量，不应自行从长篇原始 JSON 猜测结论。

每个建议须至少包含：

1. 行动建议；
2. 支撑它的指标和值；
3. 数据时间范围和质量；
4. 非医疗声明及“以主观感受为准”的提醒。

示例：

> 今天建议把训练安排为轻到中等强度。过去两天恢复信号偏低，昨夜睡眠债增加 55 分钟；HRV 数据完整，但今天的训练数据尚未同步。若你主观感到疲劳，请优先休息。

## 8. 验证与版本化

- 使用同意测试用户的 28–90 天数据离线回放，检查分数是否平稳、可解释且不受单次异常测量支配。
- 针对缺失 HRV、睡眠拆分、时区变化、手动编辑训练、重复会话等边界情形写测试样例。
- 用户可反馈“建议不符合感受”；此反馈只用于产品评估，不在一期自动改写个人生理基线。
- 每次输出记录 `metric_version`、输入记录版本和计算时间；算法改版后可对比新旧版本。

## 9. 一期验收

- 有足够数据的用户可看见三项指标及完整解释；
- 数据不足用户只会看见校准与补数提示，不会看见虚假精确分数；
- 任一建议均可追溯到具体指标和日期；
- 所有指标在同一份数据重放下得到确定性结果；
- UI 与文案不使用诊断、疾病、受伤概率或绝对安全承诺。
