# 自建恢复、睡眠与训练负荷指标设计

**状态：** 草案，待用户审阅
**日期：** 2026-08-23
**对应工作项：** 4. 定义自建恢复、睡眠、训练负荷指标

## 1. 目标与边界

Google Health 的 Readiness、Sleep Score、Cardio Load 不是公开 API 字段，且其算法不可复制。一期建立自己的透明指标，为 AI 教练提供稳定输入，并让用户能查看指标来源、基线和缺失数据。

这些指标用于生活方式与训练自我观察，**不用于诊断疾病、预测受伤或替代专业医疗建议**。

## 2. 共同设计原则

1. 每个分数都能展开为原始输入、个人基线、时间范围和版本。
2. 使用个人历史而非人群排名；同一用户的趋势比跨用户比较更重要。
3. 数据不足时显示“校准中”或低置信度，而不是生成漂亮但不可靠的数字。
4. 算法采用版本化配置；历史结果保存所用版本，避免悄悄改分。
5. 先提供可解释的规则模型，积累数据后才评估是否需要学习型模型。

## 3. 基线与数据质量

### 基线

- 初始校准：计算某个睡眠日期 `D` 的**恢复信号**时，只使用严格早于 `D` 的历史日，避免当天数据进入自己的基线。少于 14 个字段有效历史日时不显示恢复分数；有 14–27 个时使用“临时基线”；有至少 28 个时形成完整个人基线。睡眠完整度不依赖 HRV/RHR：有主睡眠即可显示时长、效率和中断子分，作息规律性在有 14 个主睡眠历史日后才加入。
- 基线窗口：从 `D` 之前向后取最近 `min(28, 字段有效历史日数)` 个有效日；使用中位数和稳健离散度（如 MAD）减小异常日影响。临时基线的窗口就是当时实际取得的 14–27 日，不补零、不混入更早日期。
- 生命体征基线按同一测量条件比较，例如优先使用夜间/晨间 HRV 与静息心率。

指标不共用一个会排除数据的“有效日”定义：

- **睡眠有效日：** 有选出的主睡眠及 `minutesAsleep`；用于睡眠完整度、睡眠债和作息规律性。
- **HRV 有效日 / RHR 有效日：** 同一睡眠日期各自有范围校验通过的 daily HRV / daily RHR；用于各自的恢复基线。
- **恢复有效日：** 有主睡眠，且 HRV、RHR、实际睡眠分钟三项原始数据中至少两项；只用于判断恢复信号可否输出。
- **训练完整日：** 当地日的活动/训练数据已同步并能明确识别有负荷或确认的零负荷；未知数据绝不当作零。

形成或使用完整 28 日基线时，用户数据源的最近一次成功同步必须距计算时刻不超过 36 小时；历史记录不会因其原始写入时间较早而失效。

`睡眠日期`固定为 Google Health API v4 `sleep.interval.civilEndTime` 的本地日历日；没有 civil time 时，使用记录的 `endTime + endUtcOffset` 计算并持久化结果。例如周一 23:30 至周二 07:00 的主睡眠归到周二。v4 不使用旧 Fitbit Web API 的 `isMainSleep` 字段：候选为结束于该睡眠日期、`metadata.nap != true` 且 `summary.minutesAsleep ≥ 180` 的 `sleep` 会话。候选中先取实际睡眠分钟最多者，再取 `metadata.processed=true`、开始时间最早、`dataPoint.name` 字典序决胜。午睡不进入主睡眠选择。保存原始 physical time、civil time 与 UTC offset，历史分数只用保存的 civil time/offset 重放，绝不以服务端当前时区重算。

对某个需要基线的子分数，先按字段有效日选择窗口，再只保留字段存在且通过范围校验的日值；不足 14 个日值时，该子分数不可用。HRV、RHR、主睡眠起止时间与训练负荷各自可用的历史日数须单独展示。

### 数据质量

每次计算附带 `high`、`medium`、`low` 或 `calibrating`；“核心输入”按指标定义，而非泛指全部数据：

| 指标 | 核心输入 | `high` | `medium` / `calibrating` | `low` |
| --- | --- | --- | --- | --- |
| 恢复信号 | 当日 HRV、RHR、睡眠完整度中的至少两项 | 三项齐全、各有 28 日基线、同步 ≤36 小时 | 两项齐全且使用 14–27 日临时基线；少于 14 日为 `calibrating` 且不出分 | 两项不足、异常或同步过期 |
| 睡眠完整度 | 主睡眠实际分钟和用户确认的睡眠目标 | 时长、卧床、清醒阶段、14 日规律性齐全 | 缺效率/中断/规律性中的一项；不足 14 个主睡眠日时为 `calibrating`，仍可展示不含规律性的部分分数 | 无实际睡眠分钟、无用户目标或异常记录 |
| 训练负荷 | 可识别的训练会话和对应负荷输入 | 心率区间或 exercise 心率区间齐全 | 会话时长与提供方强度降级计算；基线不足为 `calibrating` | 训练存在但无法得到任何强度，或数据未知 |

低质量数据只显示原始趋势和补数提示，不输出强训练建议。

## 4. 恢复信号（Recovery Signal）

### 用户目的

了解身体今天相较于自己的常态，是更适合恢复、维持训练，还是可以尝试较高负荷。

### 输入与权重

| 输入 | 默认权重 | 比较方式 |
| --- | ---: | --- |
| 夜间/晨间 HRV | 40% | 与个人 14–28 日字段基线的相对偏离；较高通常更好。 |
| 静息心率 | 30% | 与个人基线的反向偏离；持续升高需要说明。 |
| 睡眠完整度 | 30% | 使用本文件定义的昨夜睡眠指标。 |

对 HRV 和 RHR 使用以下确定性变换。令 `m` 为第 3 节为目标睡眠日期选出的 14–28 个、该字段可用的历史日中位数，`MAD` 为同一集合的中位数绝对偏差，`s = max(1.4826 × MAD, floor)`；其中 HRV 的 `floor = 5 ms`，RHR 的 `floor = 3 bpm`。

`z = (今日值 − m) / s`

- `HRV 子分 = clamp(50 + 15z, 0, 100)`；
- `RHR 子分 = clamp(50 − 15z, 0, 100)`；
- `睡眠子分 = 本文件第 5 节的睡眠完整度`。

恢复信号为可用子分按默认权重加权平均，并把可用权重归一化至 100%。HRV/RHR 子分各自需要至少 14 个同字段历史日；睡眠子分需要第 5 节可输出的睡眠完整度。少于两项核心输入时不生成分数，仅显示“数据不足”；有两项但用户数据源最近成功同步距计算时刻超过 36 小时时最多给 `low` 质量。`clamp(x, 0, 100)` 表示将结果限制在 0 到 100。

### 输出

- 分数：0–100，仅表示相对个人近期状态；
- 状态：`恢复优先`（0–39）、`维持`（40–69）、`状态较好`（70–100）。这些是 v1 的解释标签，不是医疗或安全阈值；离线回放与用户反馈未通过前，AI 不得把它升级为“加练许可”；
- 解释：最多三条，例如“HRV 比个人基线中位数低 16%，且昨夜少睡 70 分钟”；
- 不确定性：基线长度、缺失输入和异常测量提示。

不使用红黄绿配色作为医疗风险信号，也不把状态表述为“可以安全高强度训练”。

## 5. 睡眠完整度（Sleep Completeness）与睡眠债

### 用户目的

区分“睡了多久”“睡得是否连续”“作息是否稳定”，而非只给一个神秘睡眠分数。

### 输入与权重

| 输入 | 默认权重 | 定义 |
| --- | ---: | --- |
| 睡眠时长达成度 | 40% | 实际睡眠时长相对于用户设置睡眠目标。 |
| 睡眠效率 | 25% | 睡眠时长 / 卧床时长；无卧床时长则不计入。 |
| 清醒中断 | 15% | 夜间清醒总时长与次数的趋势性惩罚。 |
| 作息规律性 | 20% | 入睡/起床时间与最近 14 日个人常态的偏离。 |

为避免实现歧义，子分数固定为：

- `时长达成度 = clamp(100 × 实际睡眠分钟 / 用户目标睡眠分钟, 0, 100)`；
- `睡眠效率 = clamp(100 × 实际睡眠分钟 / 卧床分钟, 0, 100)`；
- `清醒中断 = clamp(100 − 0.75 × 夜间清醒分钟 − 5 × 清醒片段数, 0, 100)`，清醒片段仅计时长至少 5 分钟的睡眠阶段；
- `作息规律性 = clamp(100 − 0.8 × (|B−14日中位 B| + |起床时间−14日中位起床时间|), 0, 100)`，时间差以分钟计。

`作息规律性`中的入睡时间使用可比较的跨午夜坐标：令 `b` 为入睡本地钟点的午夜后分钟数；若 `b < 720`，令 `B = b + 1440`，否则 `B = b`。因此 23:30 为 1410、00:30 为 1470，两者相差 60 分钟；该规则不做环形取模。起床时间一律为主睡眠结束时刻的午夜后分钟数。14 日中位入睡/起床时间均取目标睡眠日期之前最近 14 个具有对应时间的主睡眠日（不得包含目标日）；少于 14 个时不计算规律性子分。

睡眠完整度为可用子分按表中权重归一化后的加权平均。若没有卧床时长或清醒阶段，则不计算相应子分并降低质量；少于 14 个主睡眠历史日时不计算规律性子分，但时长/效率/中断仍可组成 `calibrating` 部分分数。若缺少实际睡眠时长、用户未确认睡眠目标，或全部可用子分的原始权重不足 40%，则不生成分数。首次设置必须要求用户确认自己的睡眠目标；系统可以解释该目标的作用，但不替用户做医学化的“最佳睡眠需求”判断。

### 睡眠债

`近 7 日睡眠债 = Σ max(0, 用户睡眠目标 − 每日实际睡眠时长)`

睡眠债用“累计少睡时长”展示，而不是夸张的风险标签。午睡是否抵扣由产品设置明确说明；一期默认单独展示午睡，不自动完全抵扣主睡眠债。

## 6. 训练负荷（Training Load）与平衡

### 用户目的

知道自己最近的运动刺激相较于个人习惯是偏低、相近还是增加过快。

### 负荷算法

一期使用可解释的心率区间负荷：

`会话负荷 = Σ(每个心率区间停留分钟数 × 区间权重)`

优先使用 Google Health API v4 `exercise.metricsSummary.heartRateZoneDurations`：`light / moderate / vigorous / peak` 的分钟权重分别为 1 / 3 / 4 / 5。若会话没有该汇总但有分钟级心率，才使用心率储备百分比 `p = (HR − RHR) / (HRmax − RHR)` 分区：`p < 0.50`、`0.50–<0.60`、`0.60–<0.70`、`0.70–<0.80`、`p ≥ 0.80`；权重分别为 1、2、3、4、5。优先使用用户明确设置的 `HRmax`；否则使用 `208 − 0.7 × 年龄`。只有 `100 ≤ HRmax ≤ 230`、`HRmax ≥ RHR + 20`，且 RHR 为会话开始前最近 7 日内有效值时，才运行该降级算法；否则跳过它而不产生错误区间。

若仅有会话汇总而无区间数据，使用 `会话分钟 × 强度权重` 的最后降级算法：低/中/高强度的权重分别为 1/3/5，强度取提供方的会话强度标签；没有标签则该会话不产生训练负荷，标示为 `low` 数据质量。每个日负荷记录 `zone_summary`、`minute_hr` 或 `session_fallback` 的来源等级；混用来源的趋势只给 `medium` 或更低质量，绝不伪装为同一精度。

日负荷为训练会话负荷加总；日常低强度活动可单独展示，默认不混入训练负荷，避免把通勤和正式训练混为一谈。

### 训练—恢复平衡

- **短期负荷：** 最近 7 日平均日负荷；
- **长期参考：** 最近 28 日平均日负荷；
- **负荷比：** 短期负荷 / 长期参考；
- **恢复上下文：** 最近 3 日恢复信号和睡眠债趋势。

短期和长期平均都以日历日为分母，但只有训练完整日才能贡献确认的零负荷。过去 28 日至少有 8 个非零训练日、至少 24 个训练完整日，且长期参考至少为 5 负荷点时才显示负荷比；否则显示“训练基线校准中”。这使每周训练两到三次的用户也能获得比较，同时不会把未同步日当成休息日。负荷比小于 0.80 显示“低于近期习惯”，0.80–1.30 显示“接近近期习惯”，大于 1.30 显示“增加较快”。零短期负荷在已有长期基线且 7 日均完整时为 0；分母不足时绝不相除。它不是伤病预测器，也不是让用户强行完成的目标。

## 7. AI 教练使用规则

### 数据契约与权限

AI 只能访问短生命周期的 `coach_context`，不得读取长篇原始 JSON、refresh token、餐食照片或其他用户数据。`coach_context` 仅包含：用户选定问题、允许的最近 28 日聚合指标、最多 10 条带日期的原始证据摘要、`metric_version`、数据质量和用户确认的目标/偏好。服务端按用户 ID、字段白名单和时间范围构造该对象，模型不得自行选择或扩大数据范围。

模型只能调用只读的受控工具：`get_today_metrics`、`get_metric_trend`、`get_confirmed_meals` 与 `get_habit_experiment`。模型不能调用写回、删除、OAuth、数据库查询或任意网络工具；餐食保存、行为日志和写回均由用户在确定的 UI 中确认。

### 允许范围与安全降级

允许回答：指标含义、数据缺失解释、轻量训练/休息安排、睡眠与饮食记录习惯、以及已确认餐食的总结。禁止回答或推断：疾病、受伤概率、诊断、药物/补剂剂量、极端节食、急救、基于被动传感数据的绝对训练安全结论。

用户主动描述危险症状、急性不适、自伤风险或要求诊断时，教练停止个性化训练/饮食建议，展示预先审核的安全提示和寻求当地紧急或专业帮助的路径；不得把可穿戴数据解释为是否存在或不存在医疗风险。模型不可用、无 AI 同意、数据质量为 `low` 或引用无法验证时，退化为规则化的数据状态说明，不生成个性化行动建议。

### 输出契约与校验

每个成功回答必须输出可校验的 `coach_response`：`action`、`evidence[]`（指标名、值、日期/范围、质量）、`uncertainty`、`non_medical_note` 与 `safety_state`。后端必须逐条确认 evidence 存在于本次 `coach_context`，且行动强度不超过数据质量允许范围；任一校验失败则拒绝模型文本并显示安全降级答案。

每个建议须至少包含：

1. 行动建议；
2. 支撑它的指标和值；
3. 数据时间范围和质量；
4. 非医疗声明及“以主观感受为准”的提醒。

示例：

> 今天建议把训练安排为轻到中等强度。过去两天恢复信号偏低，昨夜睡眠债增加 55 分钟；HRV 数据完整，但今天的训练数据尚未同步。若你主观感到疲劳，请优先休息。

## 8. 验证与版本化

- 使用同意测试用户的 28–90 天数据离线回放，检查分数是否平稳、可解释且不受单次异常测量支配。
- 针对缺失 HRV、只有睡眠数据、睡眠拆分、时区变化、手动编辑训练、重复会话、HRmax 无效、未知训练日和混合负荷来源等边界情形写测试样例。
- 用户可反馈“建议不符合感受”；此反馈只用于产品评估，不在一期自动改写个人生理基线。
- 每次输出记录 `metric_version`、输入记录版本和计算时间；算法改版后可对比新旧版本。
- 对 AI 教练运行至少 50 条固定安全与引用测试：100% 引用能追溯到输入，0 条越权写入/诊断/绝对训练安全结论；失败回答必须降级而非展示。

## 9. 一期验收

- 有足够数据的用户可看见三项指标及完整解释；
- 数据不足用户只会看见校准与补数提示，不会看见虚假精确分数；
- 任一建议均可追溯到具体指标和日期；
- 所有指标在同一份数据重放下得到确定性结果；
- 只有睡眠数据的用户仍可获得睡眠完整度的部分分数；HRV/RHR 不足的用户不会看到伪造的恢复分数；
- 训练两到三次/周且同步完整的用户可在满足 8 个训练日后获得负荷比较；未知日不作为零负荷；
- UI 与文案不使用诊断、疾病、受伤概率或绝对安全承诺。
