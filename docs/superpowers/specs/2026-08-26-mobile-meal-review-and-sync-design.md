# 手机端餐食审阅、AI 修改与显式同步设计

**状态：** 用户确认，待实现

**日期：** 2026-08-26
**补充并取代范围：** 本文取代 `2026-08-26-photo-nutrition-google-health-design.md` 中一期餐食编辑后的版本保留和写回触发方式；照片校验、台湾食药署数值来源、Google Health payload 映射与 outbox 的可靠性约束仍然有效。

## 1. 目标与非目标

移动端用户上传一张餐食照片后，获得按菜拆分的完整营养清单；可以直接改食材、份量或单个营养数值，也可以询问 AI 获得**待确认的**修改建议。用户点击“保存修改”才更新本地餐食，点击“同步这一餐”才写入 Google Health。

一期非目标：

- 自动同步、批量同步、餐食营养搜索。
- 保存原图、识别原始结果、修正历史或 AI 聊天历史。
- AI 自动应用建议，或 AI 直接调用 Google Health 写接口。
- 医疗建议、缺乏诊断或营养目标功能。

## 2. 已确认的产品规则

| 主题 | 决定 |
| --- | --- |
| 主平台 | 手机浏览器优先；桌面仅做同一信息架构的双栏适配。 |
| 保存与同步 | 两步：先“保存修改”到本地，再由用户点“同步这一餐”。 |
| 同步粒度 | 只同步当前一餐（其下全部菜品），不提供“同步全部未同步餐食”。 |
| 菜品/食材编辑 | 改菜名、食材或食材克数后，重新从本地台湾 FDA 数据计算该道菜全部营养。 |
| 营养项编辑 | 改热量或某一个营养值时，只覆盖该项，其他项目不变。 |
| 重算与覆盖 | 食材或份量重算会替换该菜当前全部营养，包括此前的单项营养修改；不保留被替换值。 |
| 历史 | 一期只保留最新餐食数据；没有原始识别值、修改历史或历史版本界面。 |
| AI | AI 生成结构化建议，用户逐项应用或忽略；不自动改值。 |
| 图片与聊天 | 照片只存在于上传/当前编辑页面的浏览器内存和模型调用期。保存、刷新或离开后不再显示。AI 聊天在当前页面会话中可继续，刷新后从该餐最新结构化数据重新开始。 |

## 3. 状态与主流程

```text
上传照片
  → AI 识别草稿（照片不落盘；不写 Google）
  → 手机端编辑中
       ├─ 编辑食材/克数 → 重新计算该道菜 → 覆盖该菜当前营养
       ├─ 编辑某项营养 → 只覆盖当前项
       └─ 问 AI → 待处理建议 → 用户应用/忽略
  → 保存修改（仅本地最新快照）
  → 已保存 · 未同步
  → 同步这一餐（明确用户动作）
       ├─ 同步中
       ├─ 已同步
       └─ 同步失败 / 同步恢复中 → 用户重试这一餐
```

本地保存从不产生 Google 请求。同步完成后，用户再次修改本餐会将状态切回“有未同步修改”。同步期间编辑和再次同步按钮禁用，避免本地快照与本次 outbox payload 不一致。

## 4. 手机页面与交互

### 4.1 餐食编辑页

页面只显示当前餐食的最新值：

1. 顶栏：返回、餐次/进食时间、同步状态（`草稿`、`已保存·未同步`、`同步中`、`已同步`、`同步失败`）。
2. 识别/编辑当次才显示照片缩略图；已保存餐食不显示图片占位。页面始终显示菜名与进食时间。
3. “编辑菜品与食材”进入全屏页面，可编辑每道菜名称、食材和食材克数。提交后立即重算该道菜并覆盖其所有营养项。
4. “完整营养”按固定分组展示：能量与宏量、维生素、矿物质、其他本地已知成分。默认展开能量与宏量；其余分组折叠并显示已知条数。未知值显示“未知”，不凭空显示 0。
5. 点任一营养行打开底部编辑弹层：显示名称、当前数值、适用单位（热量为 kcal；重量为 g/mg/μg）和保存按钮。输入必须为有限、非负数；保存即更新当前项。
6. 页面无营养搜索入口。用户通过固定分组浏览全部项目。
7. 底部固定两个动作：`保存修改` 与 `同步这一餐`。草稿仅显示保存；未保存或无可写 Google 字段时同步按钮禁用并给出原因。

桌面端复用同一结构，但将 AI 区固定于右栏；手机端 AI 采用底部弹层，不挤占营养清单。

### 4.2 AI 助手

“问 AI 修改这餐”打开底部对话弹层。模型每次只接收当前结构化餐食：餐次、时间、菜品、食材、克数、当前营养项和用户新问题；不接收 OAuth token，也不在保存后接收原照片。

模型返回严格的 `suggestions[]`，而不是直接写数据库：

```json
{
  "suggestions": [
    {
      "scope": "dish",
      "dishId": "current-dish-id",
      "kind": "replace_ingredients",
      "summary": "鸡蛋改为嫩豆腐；食用油 15 g 改为 5 g",
      "requiresRecalculation": true,
      "patch": { "ingredients": [] }
    }
  ]
}
```

AI 建议卡显示“待处理建议 N”。点“查看建议（N）”进入对比页，逐项显示变化和影响：

- 食材/克数建议显示“应用后重新计算这道菜全部营养”。
- 单项营养建议显示“只修改此项”。
- 用户可应用单项、应用全部或忽略；应用才改变编辑态。AI 请求或解析失败只显示错误，不改变餐食。

聊天消息只保留在当前浏览器会话。刷新后可以对同一已保存餐食发起新对话，但不恢复旧消息；若问题依赖视觉内容，AI 明确要求重新上传照片。

## 5. 本地最新快照与 API 边界

页面和服务均把一餐视为一个稳定的“当前餐食”而非用户可见的版本历史。保存和后续编辑以事务替换该餐的当前 dishes、ingredients、nutrients、当前同步状态与当前 Google links；被替换的本地营养事实不另存历史。

为支持页面，新增或调整以下受 session 保护的接口；路径统一位于 `/rhythm` 前缀下：

| 接口 | 作用 |
| --- | --- |
| `POST /api/meals/photo` | 现有照片识别。返回当前编辑所需的草稿和营养结果；浏览器自行持有临时照片预览。 |
| `GET/PATCH /api/meals/drafts/:id` | 获取或覆盖当前草稿的菜、食材、克数与单项营养编辑。对食材类 patch 在服务端重算。 |
| `POST /api/meals/drafts/:id/ai-suggestions` | 以当前结构化草稿请求 AI；只返回 suggestions，不持久化消息或建议。 |
| `POST /api/meals/drafts/:id/save` | 保存为本地当前餐食，返回稳定的 `mealId` 和 `未同步` 状态；不建写回 outbox。 |
| `GET/PATCH /api/meals/:id` | 读取或替换已保存餐食当前值。修改后标为 `有未同步修改`。 |
| `POST /api/meals/:id/sync` | 明确请求同步这一餐。检查权限后为当前快照入队，不接受批量 ID。 |

服务端是唯一的营养计算权威：前端不能自行计算/合并营养，也不能直接构造 Google payload。营养覆盖和食材编辑必须在同一事务内写入当前餐食，避免保存一半数据。

## 6. Google 同步规则

`POST /api/meals/:id/sync` 同时满足下列条件才入队：该餐已本地保存、当前有未同步改动、账户级写回开关开启、连接为可用状态、已授 nutrition write scope、至少有一个可写字段。

首次同步为该餐当前每道菜创建一个 anonymous `nutrition-log`。已同步餐食修改后的下次同步，先删除其旧 Google data points，再创建当前菜品对应的新 data points；本地只保留当前 Google link 以便安全删除，不把旧营养数据当作历史展示。

写入沿用既有 outbox 的确定性名称、payload hash、两分钟 lease、30 秒请求 deadline 与精确名称 GET 恢复规则。替换流程若删除成功但创建失败，页面状态为“同步恢复中”，绝不显示为已同步，也不自动生成额外重复 log；用户只能对这一餐发起重试。页面只显示聚合状态，不显示 token、payload 或原图。

## 7. 错误与空数据

| 情况 | 页面行为 |
| --- | --- |
| 图片不符合格式、大小或像素限制 | 留在上传页，说明原因；不调用模型。 |
| AI 识别/建议失败 | 保留当前草稿，允许直接编辑或重试；不产生修改。 |
| 食材未命中或营养缺失 | 显示“未知”；用户可补填单项，不用模型或宏量推断为 0。 |
| 食材编辑后重算 | 明确提示会覆盖该菜当前营养值；确认后替换。 |
| 未登录/缺写权限/账户写回关闭 | 同步按钮说明原因并引导到账户页；不创建 outbox。 |
| 同步超时或状态未知 | 显示“同步恢复中/待确认”，不自动重复 create。 |

## 8. 验收与测试

- 手机宽度 320–430 px 下，编辑、AI 弹层与底部动作均可单手触达，且底部动作不遮挡内容。
- 上传并识别后，营养分组显示所有本地已知字段；没有搜索入口。
- 手改一个营养项只变该项；食材或克数更改会重算并覆盖该菜所有当前营养。
- AI 建议未经“应用”不会改变草稿；刷新不恢复对话，已保存后的新对话没有原图。
- “保存修改”从不调用 Google；只有“同步这一餐”会为该餐入队。
- 已同步餐食编辑后回到未同步状态；下一次同步不会让旧、新 Google log 双计。
- 不持久化照片、原始识别值、营养修正历史或聊天消息；日志不含图片、token 或 payload。
